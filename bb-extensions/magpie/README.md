# Magpie connector for BB

Connect BB's Pi, Codex, and Claude Code providers to a Magpie gateway. Monitor its usage and subscriptions from the Magpie page in BB. Magpie manages accounts and models. This plugin forwards requests through the BB server and can install a Pi extension on enrolled machines.

The Pi extension is generated by this plugin. It needs the proxy address and token that BB supplies to a Pi session. It is not a separate package for standalone Pi sessions.

## Requirements

- BB 0.45 or later, with the providers you want to use installed.
- A configured Magpie gateway that the BB server can reach. Desktop, CLI, and container deployments use the same gateway interface.
- For Pi: a Magpie-generated `models.json` with a `providers.magpie` entry on the BB server, and the Pi CLI on each execution machine.

The gateway can run on the BB server or another machine. The Pi source files must be readable by the BB server, even when the gateway runs elsewhere. Native Codex and Claude Code routing does not need Pi configuration.

## Install

From this plugin directory:

```sh
npm ci --include=dev --legacy-peer-deps
bb plugin build .
bb plugin install .
```

The plugin ID is `magpie`. A fresh installation leaves native routing and automatic Pi sync off. Configure the gateway before enabling either feature.

## Gateway settings

The default gateway is `http://127.0.0.1:3425`. Set `gatewayUrl` to the HTTP or HTTPS origin that the BB server can reach. Paths, query strings, and embedded credentials are not accepted.

```sh
bb plugin config magpie set gatewayUrl http://127.0.0.1:3425
bb magpie check --native
```

If the gateway requires a key, set `gatewayKey` in the Magpie plugin settings in BB. This includes a Docker gateway that requires a key for requests from the host. Keep credentials out of source files and shell history.

The plugin creates its own `proxySecret` to authenticate enrolled machines. Changing that secret revokes existing machine tokens. If you clear it, reload the plugin to create a new secret.

## Monitor in BB

Open **Magpie** in the BB navigation rail. The page shows usage for Today, 7 days, or 30 days:

- **Estimated cost** and the token share of each agent.
- **Tokens or cost over time**, per hour for Today and per day otherwise, split by agent.
- **Processed tokens, cached input, output, and requests**, with a trend line for each.
- **Subscriptions:** the allowance used in each subscription window.
- **Breakdown** by model, agent, or time bucket.

The data includes gateway requests and supported agent session logs. Period boundaries use the Magpie server's time zone. Costs use model list prices; they are not invoices. Requests without a known price are marked.

**Open Magpie Web** opens the Web UI in a new browser tab for accounts, routing, and settings. Sign in there with the Web UI key. The link uses `webLink`, or `webUrl` when `webLink` is empty. A `127.0.0.1` address opens only on the device that runs the browser. For remote access, set `webLink` to an address that the browser can reach, such as a LAN address or the URL from `bb connect expose 3430`.

The Magpie button in the sidebar footer opens a compact subscription allowance view, like BB's Provider usage. It refreshes every 30 seconds while open.

The page and the footer view follow the browser language: Chinese for `zh` locales, English otherwise. Messages from Magpie and from model sync stay in English.

The page refreshes every 15 seconds after a completed read while visible. Refresh requests another snapshot. The server shares each snapshot for up to 5 seconds, so several open pages do not duplicate requests.

Health and usage use `gatewayUrl` and `gatewayKey`. For subscriptions and provider status, run `magpie web` and set these plugin settings:

- `webUrl`: the Web UI HTTP(S) origin as reached from the BB server, for example `http://127.0.0.1:3430`. Do not include a path or login query.
- `webLink` (optional): the HTTP(S) URL that your browser opens for **Open Magpie Web**. It can include a path. Credentials are removed.
- `webKey`: the Web UI key. Set this secret in **Settings → Plugins → Magpie**. A fixed `MAGPIE_WEB_KEY` avoids updates after each Web UI restart.

The BB server signs in to the Web UI. The browser receives only monitoring fields. Keys, cookies, request content, session identifiers, and raw upstream error bodies are omitted. The monitor uses GET requests only. It does not change Magpie settings or routes. There is no browser iframe or public Web UI proxy.

Gateway access keys restricted to models, accounts, or a budget cannot read the global usage summary. The page reports that access failure and keeps the other sections available.

The adapter is checked against Magpie `0.1.1190`. It validates the fields it reads and reports incompatible responses per section. HTTP redirects are not followed. Source responses are limited to 4 MiB.

## Pi

On the machine where Magpie manages the source Pi configuration, select a model:

```sh
magpie models pi
magpie pi <provider/model>
```

The plugin reads `models.json` and `settings.json` from `piAgentDir` on the BB server. Its default is the server process's `PI_CODING_AGENT_DIR`, or `~/.pi/agent` when that variable is unset. Set `piAgentDir` to an absolute path when the source files are elsewhere.

Check the configuration, then sync a selected machine:

```sh
bb magpie check
bb machine list
bb magpie sync --machine <machine-name-or-id>
```

Omit `--machine` to sync all connected persistent machines. Sync installs `extensions/magpie/index.js` in each machine's Pi directory and sets `defaultProvider`, `defaultModel`, and `enabledModels`. It saves the prior values for removal and preserves other settings. It does not change `models.json` or `auth.json`.

Sync also writes Magpie models into the top-level `customModels` list in BB's `config.json`, then reloads the BB config. Codex then lists the Claude and DeepSeek models, and Claude Code lists the GPT and DeepSeek models. Sync skips models that the native picker already lists and dated aliases. It replaces only entries whose `displayName` starts with `Magpie · `, so it also removes models that Magpie no longer serves. It saves the prior file as `config.json.magpie.bak`. These entries work only on threads that route through Magpie. Turn off `streamerMode` to see them.

The **Sync models** button in the Magpie panel runs the same sync. When no Pi thread is running, sync also reloads the Pi provider. Otherwise, refresh it later:

```sh
bb plugin reload provider-pi
```

Start a BB thread with the **Pi** provider and a `magpie/<provider>/<model>` model. Existing Pi sessions need to restart to load the extension. BB model lists can retain old entries for up to 10 minutes.

To keep all persistent machines in sync, enable automatic sync:

```sh
bb plugin config magpie set autoSync true
```

When enabled, the plugin checks the source catalog every 30 seconds. It updates changed catalogs, retries when machines reconnect, and refreshes the Pi provider when all Pi threads are idle. Set `autoSync` to `false` to return to manual sync. Existing installations keep their saved setting.

On each execution machine, the host worker uses `PI_CODING_AGENT_DIR` or `~/.pi/agent`. The BB host daemon and Pi must use the same directory. Project settings can override Pi's global defaults.

These settings also affect Pi started from a terminal. The generated extension requires BB session environment variables for model requests. Use a different provider outside BB, or remove the extension first.

## Native Codex and Claude Code

Route one thread through Magpie:

```sh
bb magpie check --native
bb magpie route <thread-id>
```

Changes apply on the next turn. To stop routing that thread, use `bb magpie route <thread-id> --off`. A per-thread setting takes precedence over the global routing setting.

To route all native threads for a provider:

```sh
bb magpie routing codex
bb magpie routing claude
```

Use `--off` with either command to turn off that global route. Per-thread settings remain in effect. The models selected in BB must be available from Magpie.

Account Pooler is optional. If it is enabled, avoid routing the same provider through both plugins. Use `bb pool bypass <thread-id>` for a single thread, or `bb pool routing <codex|claude> --off` before enabling a global Magpie route. Restore those Account Pooler settings separately when switching back.

## Data and credentials

The plugin sends model metadata and a machine token to each execution machine. Gateway credentials stay on the BB server. Source model URLs, headers, and credentials are not copied into the generated extension. The plugin does not execute `apiKey` commands from `models.json`.

Requests use the machine's existing BB connection. The plugin forwards the supported chat, responses, and messages API routes. It does not expose the Magpie Web UI or configure Magpie startup, Docker, or network access. Monitoring reads the Web UI through the BB server when configured.

## Status and removal

```sh
bb magpie status
bb magpie remove --machine <machine-name-or-id>
```

Removal restores the saved Pi selection fields if the user has not changed them since the last sync. It removes only the managed extension entry. A machine removed this way is excluded from automatic sync until you explicitly sync it again.

Before uninstalling, connect every machine that received the extension, run `bb magpie remove` without `--machine`, and check that each machine reports success. This also turns off automatic sync. Refresh the idle Pi provider with `bb plugin reload provider-pi`, then disable or uninstall the plugin. Disabling the plugin alone does not restore Pi files.

## Development

Use Node.js 24 and the Pi CLI. Run these commands from this directory:

```sh
npm run typecheck
npm test
npm run verify:pi
bb plugin build .
```

The tests use temporary files and real local HTTP servers. Monitor tests cover login, secret filtering, response validation, partial failure, caching, periods, and redirect refusal. `verify:pi` runs the real Pi CLI against three fixture APIs and writes `.artifacts/pi-e2e.json`. It does not send model requests to production accounts.

The plugin uses BB Plugin SDK 0.6.37 and BB's existing provider environment hooks. `pi-extension.ts` generates the Pi extension. Edit that source file, not the installed copies.
